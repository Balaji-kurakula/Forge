# Code of Conduct

## The short version

Be decent to people. Discuss the code, not the person writing it.

## Expected behaviour

- Assume good faith. Most disagreements are missing context, not bad intent.
- Give feedback on the work: what is wrong, why it matters, what would be better.
- Accept feedback the same way. A rejected patch is not a rejected person.
- Respect that this is a side project maintained in spare time. Reviews may be slow.

## Unacceptable behaviour

- Harassment, personal attacks, or demeaning comments — including about someone's identity,
  background, or level of experience.
- Sexualised language or imagery, or unwelcome attention of any kind.
- Publishing others' private information without explicit permission.
- Sustained disruption of discussions, or deliberate bad-faith argument.

## Scope

This applies in every project space — issues, pull requests, discussions, commit messages — and
whenever someone is representing the project in public.

## Enforcement

Report problems by opening a private security advisory (**Security** tab → **Report a
vulnerability**), which is the only private channel this repository has. Reports stay confidential.

The maintainer may edit or delete comments, close issues or PRs, or block accounts, in proportion
to the behaviour. There is no appeals process; this is a one-person project, not an institution.
